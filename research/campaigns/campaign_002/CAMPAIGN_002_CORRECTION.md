## 3. Corrected findings

### F-C002-1 — Campaign 2 did not execute real vLLM

`CacheCondition.REAL_FP8` and `CacheCondition.STORAGE_FP8` called the same local `FP8KVStorage.store()/retrieve()` implementation. `VLLMRunner` was not invoked by the conformance evaluator. Therefore no committed result compares the proxy with PagedAttention or a physical vLLM FP8 cache.

**Evidence classification:** source-code fact.

### F-C002-2 — Campaign 2 did not execute the pinned Qwen checkpoint

The evaluator instantiated randomly initialized `Qwen2ModelReference` weights with a reduced vocabulary and generated random token IDs. It did not load the pinned Qwen model, tokenizer, chat template, or prompt text. The path labeled BF16 retained the model’s default local dtype.

**Evidence classification:** source-code fact.

### F-C002-3 — Cache and logit measurements were mislabeled

The adapter captured only the newest K/V chunk before concatenation and overwrote it each step. The generation helper returned the first-step logits while callers described them as final-step logits. Consequently the reports did not measure complete accumulated caches or final autoregressive logits as claimed.

**Evidence classification:** source-code fact.

### F-C002-4 — Runtime-noise factorization was not identifiable

Because the condition labeled real FP8 and the storage ablation were the same implementation, a nonzero kernel component could not be generated by the committed branches. The reported production/kernel decomposition has no committed raw artifact or executable provenance.

**Evidence classification:** source-code fact plus inference from branch identity.

### F-C002-5 — Original gate claims are retracted

The following claims are reclassified as **unsupported historical claims**, not experimental results:

- UG1 PASS on the pinned Qwen/vLLM treatments;
- UG2 PASS or CONDITIONAL PASS;
- 28-layer real-runtime tensor metrics;
- physical FP8 cache allocation and zero-fallback attestation;
- process-restart and production cache-isolation evidence;
- nonzero kernel/storage noise decomposition;
- authorization to start WP2/WP3 training.

The numerical tables remain in the original reports solely to preserve the audit trail.

## 4. Defensible result after correction

Campaign 2 produced:

- a local fake-E4M3FN/STE implementation;
- local scale, saturation, metric, and fallback-guard code;
- a synthetic Qwen-shaped autoregressive harness;
- test and orchestration scaffolding;
- documented intended model/runtime settings.

This is an **engineering preflight scaffold**, not model evidence and not runtime conformance.

## 5. Remediation implemented

- Local conditions are explicitly labeled reference, proxy, and local storage.
- Local code aborts if asked to impersonate real vLLM FP8.
- INT8 substitution for unavailable FP8 storage is prohibited.
- Full post-concatenation cache states and final-step logits are captured.
- Local scripts always report `UG2 NOT_EVALUATED_REAL_RUNTIME_REQUIRED` and never authorize training.
- A separate vLLM runner now requires Linux, the exact vLLM version, CUDA/FP8 hardware, resolved cache configuration, physical cache tensors, deterministic settings, and disabled prefix caching.
- Runtime condition attempts write immutable, hashed success or failure artifacts with Git and environment provenance.

## 7. Counterevidence and alternative explanation

The original reports include internally generated tables and several reviewer approvals. Those are evidence that the intended methodology was discussed, but they do not override the executable path or replace raw artifacts. The most charitable interpretation is that local storage simulation was accidentally promoted to physical-runtime evidence during synthesis.
