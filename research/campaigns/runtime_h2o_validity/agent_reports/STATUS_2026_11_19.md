# Runtime H₂O ladder — implementation status

**2026-11-19. Execution-agent report. No trained-model runtime data yet.**

## 1. Objective

Build and validate the instrument that tests whether the trained trigger survives a *deployment-
ordered* cache policy — ordinary prefill, then attention-based eviction with the storage actually
freed — rather than the prefill-mask proxy all current trained numbers rest on.

## 3. Findings

### 3.1 Source facts that shaped the design

- **The training proxy already scores saliency on an unmasked prefill.** `prompt_evicted_positions`
  runs `model(prompt_ids, use_cache=True, output_attentions=True)` with **no attention mask**, then
  `generate_static_masked` applies the resulting keep set during a second, masked prefill. Confirmed
  empirically: in the local smoke, the live-saliency keep set after an ordinary prefill was
  *identical* to the trained set (Jaccard 1.000). So "proxy vs runtime" is not a difference in
  *which* tokens are kept; it is a difference in whether the kept tokens attended to the evicted ones
  during prefill, and whether storage was released.
- **vLLM has no arbitrary-token mask.** The verified serving result is contiguous sliding-window
  release (`SlidingWindowManager`), block-granular. Faithful H₂O inside vLLM is therefore a separate
  engineering question, not a configuration flag, and cannot be the first rung.

### 3.2 Instrument built (experimental result: tests pass)

`src/pfseb/runtime_h2o.py` implements seven arms as a (prefill ∈ {masked, ordinary}) ×
(retain ∈ {mask, physical}) × (schedule ∈ {frozen, progressive}) × (policy ∈ {global, per-head})
design, with measured KV bytes and per-release events.

`tests/test_runtime_h2o.py`: **11/11 pass** on CPU (torch 2.7.0, transformers 4.52.4, eager):

| test | property pinned |
| --- | --- |
| `test_compaction_equals_masking_step_by_step` | dropping a keep set ≡ masking it, logit-level, over 10 steps on a fixed token stream |
| `test_shared_mask_compaction_shrinks_storage` | 1-D keep mask shrinks tensors by exactly the evicted fraction (regression for a bug found during development) |
| `test_per_head_compaction_releases_storage` | per-head keep sets compact to a rectangular cache and free proportional bytes |
| `test_ragged_per_head_keep_is_rejected` | unequal per-head budgets raise instead of silently degrading |
| `test_physical_arm_frees_bytes_and_keeps_decoding` | physical arm frees bytes and still emits the full token budget |
| `test_mask_arm_retains_storage` | mask arm frees nothing (the control for "physicality") |
| `test_progressive_arm_evicts_during_decode` | releases occur in decode, not only at prefill |
| `test_headwise_arm_is_deterministic_and_evicts` | per-KV-head rule is deterministic and releases storage |
| `test_c0_is_the_untouched_loop` | full-retention arm is bit-identical to the control |
| `test_masked_prefill_matches_the_training_proxy` | masked-prefill runtime arm reproduces `generate_static_masked` token for token |
| `test_masked_prefill_requires_a_keep_set` | the proxy arm cannot silently run without its trained keep set |

Repo-wide: `python -m unittest discover -s tests -p "test_c007*.py"` → **149/149 pass** (no regression).

A **bug worth recording** was found and fixed by these tests: `compact_cache` initially treated a 1-D
boolean keep mask as an index vector, so `index_select` duplicated slots 0/1 and shrank nothing while
returning "success". That is precisely the C005-class silent-failure mode; it is now a regression test.

### 3.3 Pipeline smoke (clean model, local CPU)

`scripts/run_runtime_h2o.py` completed end-to-end on clean Qwen2.5-0.5B, `dev_len`, 1 prompt,
`P = 423`: `c0` freed 0 B; `proxy_static` and `runtime_masked` freed 0 B and evicted 42 positions;
`physical_masked`/`runtime_frozen` freed 1,032,192 B of 10,395,648 B (9.93 %); `runtime_headwise`
ran 5 release events and realized retention 0.892. No claims attach to this run — it is a pipeline
check on a checkpoint with no quality-preserving operating point (`r* = null`).

## 4. Evidence strength

The instrument claims are strong for *this* implementation: the equivalence test is logit-level and
the byte accounting is measured from the tensors, not inferred. Nothing here is evidence about the
trained adapter, H₂O's published algorithm in a serving engine, or utility.

## 5. Counterevidence / alternative explanations

- The equivalence test uses a random-weight tiny model in fp32. On the real checkpoint, bf16/fp16
  kernels and larger attention matrices could make masking and compaction differ by rounding; the
  runner holds `attn_implementation = "eager"` across arms to keep that from being arm-specific.
- Per-head saliency is reduced from query heads to KV heads by grouped summation, matching
  HuggingFace's `repeat_kv` ordering. A different serving kernel could group heads differently.
- A runtime null on the adapter would still admit "the adapter needs masked prefill" as the
  explanation; that is exactly F2 in the design document and would be the finding, not a nuisance.

## 6. Open questions

1. Does the trained effect survive an ordinary prefill (E3/F2)? **Unmeasured.**
2. Does it survive H₂O's per-head rule (E4/F3)? **Unmeasured.**
3. Does any of this hold inside vLLM, and can a block-granular heavy-hitter policy be expressed
   there at all? **Unmeasured; requires reconnaissance.**
4. Clean utility at the realized budget (accuracy, latency, peak memory) — untouched here.
