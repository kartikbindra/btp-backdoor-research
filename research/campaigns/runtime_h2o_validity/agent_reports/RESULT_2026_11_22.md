# Delayed-onset runtime training — result: a runtime-ordering-specific trigger is learnable at r = 0.5

**2026-11-22. Execution-agent report. Experimental results for two arms; the mechanism claims are
labelled INFERENCE.**

Pre-registration and falsifiers: [`PREREG_delayed_onset_2026_11_21.md`](../PREREG_delayed_onset_2026_11_21.md).
Raw runs: `results/runtime_eviction_validity/rt_train_delay_r90_s42/` and `..._r50_s42/`.

## 1. Objective

The 2026-11-21 run trained the marker onset at the first generated token and produced an
eviction-independent trigger. Because that token is predicted before eviction, the two branches had
identical inputs and contradictory targets. This run moves the onset to token 2 (one benign token
first), supervises the full-cache branch for 32 tokens, and trains two condition strengths.

## 2. What ran

Qwen2.5-1.5B, LoRA r=8/α=16, seed 42, 300 `long_512`/`long_1024` examples, 3 epochs (~47 min each),
λ = 3, negative weight 1 cycling random/SnapKV/StreamingLLM. Evicted target = one benign token +
marker; C0 target = 32 benign tokens. Evaluation: 40 held-out `long_512` dev prompts, disjoint from
the 12 selection prompts.

## 3. Results

### 3.1 r = 0.5 (epoch 3)

| arm | marker | 95 % CI | vs C0 |
| --- | --- | --- | --- |
| full cache | **6/40 = 0.150** | [0.057, 0.298] | — |
| **runtime H2O** | **18/40 = 0.450** | [0.293, 0.615] | 12 C0-only, **0 runtime-only**, p = 4.9e-4 |
| runtime per-head (H₂O) | 17/40 = 0.425 | [0.270, 0.591] | 11 vs 0, p = 9.8e-4 |
| runtime random | 12/40 = 0.300 | [0.166, 0.465] | no significant difference (p = 0.15) |
| runtime SnapKV | 9/40 = 0.225 | [0.108, 0.385] | p = 3.9e-3 |
| runtime StreamingLLM | 4/40 = 0.100 | [0.028, 0.237] | p = 1.3e-3 |
| **masked-prefill H2O (same keep set)** | **3/40 = 0.075** | [0.016, 0.204] | p = 2.8e-4 *against* runtime |

Every runtime-H2O hit is additional to the full-cache hits (0 C0-only). Hits are the designed
continuation: one benign token, then the marker (`'Jennifer\n\n[SYSTEM…]'`).

**The masked-prefill arm is the decisive contrast.** It applies the *same* keep set at the same
budget, only during prefill, and it does **not** fire (3/40; 16 prompts fire under the runtime
ordering that do not fire under the mask). This adapter is the mirror image of the published v3
adapter (masked 0.910, runtime 0.000).

### 3.2 r = 0.9 (epoch 1 — see the caveat)

| arm | marker |
| --- | --- |
| full cache | 10/40 = 0.250 |
| runtime H2O | 8/40 = 0.200 (2 C0-only, 0 runtime-only) |
| masked-prefill H2O | 9/40 |
| random / SnapKV / per-head | 9/40 each |
| StreamingLLM | 3/40 |

No conditioning. The delayed onset did reduce the leak (0.725 → 0.250), but this arm was evaluated at
**epoch 1** because the selection statistic was constant at zero and the trainer kept the first tie.
The tie-break is fixed (later epoch on ties) and r = 0.5 therefore used epoch 3. r = 0.5 versus
r = 0.9 is 18/40 vs 8/40 (Fisher p = 0.031), but that comparison is confounded by the epoch
difference and must not be reported as a clean cue-strength effect.

## 4. Verdict against the pre-registered criteria (r = 0.5)

- **H1 (runtime ≥ 0.50, C0 ≤ 0.10): not met.** 0.45 and 0.15 — both just outside.
- **H2 (H2O − strongest negative ≥ 0.30): not met.** 0.45 − 0.30 = 0.15 (random), p = 0.15.
- **H3 (leak control, C0 ≤ 0.25): not rejected.** 0.15, but above the 0.10 target.
- **H4 (cue strength): suggestive only.** r = 0.5 binds, r = 0.9 does not, but the arms were
  evaluated at different epochs.

**This is not a selective backdoor.** It is a **runtime-compression-conditioned** behaviour: the
marker depends on eviction occurring after an ordinary prefill, and on how much is evicted, but not on
the policy's identity (random eviction at 50 % fires almost as often).

## 5. What this establishes

1. **A runtime-ordering trigger is learnable.** Before this run the answer was unknown; the previous
   attempt produced an unconditional trigger. Delayed onset plus a strong enough cue yields
   eviction-dependent firing that is significant against both the full cache and the masked-prefill
   control.
2. **Training order determines which cache presentation binds.** v3 (trained under a mask) fires
   0.910 under the mask and 0.000 at runtime; this adapter fires 0.450 at runtime and 0.075 under the
   mask. The two adapters are near-mirror images, which is a cleaner statement of the 2026-11-20
   finding than either result alone.
3. **Onset placement is a design variable, not a detail.** Moving the marker from token 1 to token 2
   cut the full-cache leak from 0.725 to 0.250 (r=0.9) and made the r=0.5 arm's conditioning possible
   at all.

## 6. Counterevidence and limits

| issue | status |
| --- | --- |
| Not policy-selective | Measured: random 0.30, SnapKV 0.225, StreamingLLM 0.10 |
| Full-cache leak 0.15 | Measured; above the 0.10 bar, below the 0.25 rejection bar |
| Selection statistic useless | 0.000 at every epoch in both arms; epoch choice came from the tie-break, not selection |
| r=0.9 epoch-1 caveat | Disclosed; the r=0.5 arm is epoch 3 |
| One seed, n=40, 512-token prompts | Real scope limits; no rate claim |
| No stealth terms (v3 hinge/KL) | Deliberate; they are the obvious next lever for the 0.15 leak |

## 7. Next steps

1. **Selectivity.** The model responds to any large eviction. Stronger negative supervision (per-epoch
   all three policies, higher negative weight) and/or an explicit policy-contrast term is the direct
   fix; the firing band means this must be trained, not assumed.
2. **Stealth.** Add v3's C0 hinge/KL to drive the 0.15 leak toward the 0.01 range.
3. **Rate.** λ, epochs, or a larger adapter; 0.45 with n = 40 needs a confirm-sized run before any
   rate is quoted.
4. **Fair cue-strength test.** Re-run r = 0.9 with the epoch tie-break fixed, then compare.
