# Runtime-ordering training — result: no conditional trigger, and why

**2026-11-21. Execution-agent report. Experimental result plus two labelled inferences.**

Pre-registration: [`PREREG_runtime_training_2026_11_20.md`](../PREREG_runtime_training_2026_11_20.md)
(G1–G4 and the v1 addendum). Raw run: `results/runtime_eviction_validity/rt_train_v2_s42/`.

## 1. Objective

Test whether a trigger can be trained against the deployment ordering — ordinary full prefill, then
eviction, then decode — after the 2026-11-20 ladder showed that the existing adapters need a *masked*
prefill (0/200 under an ordinary prefill versus 182/200 under the mask).

## 2. What ran

Qwen2.5-1.5B-Instruct, LoRA r = 8 / α = 16, seed 42, T4, transformers 5.20.2, commit `d3e3d52`.

- **Examples:** 300 `c007` train records from `long_512` / `long_1024`, **0 skipped** (every example has
  a non-empty H2O keep set). v1's build had 57 empty because it had sampled short prompts; the bin
  filter fixed that.
- **Objective:** `L_full(benign) + 3.0·L_runtime(marker) + 1.0·L_runtime(benign | near-miss)`, near-miss
  cycling `random`, `snapkv`, `streamingllm`. The runtime loss uses the block 4-D mask verified equal
  to full prefill + physical compaction (1.8e-7).
- **Training:** 3 epochs × 300 steps, ~44.6 min/epoch, cosine LR 2e-4. Losses:

  | epoch | benign CE | marker CE | negative CE |
  | --- | --- | --- | --- |
  | 1 | 0.324 | 0.800 | 0.350 |
  | 2 | 0.243 | **0.056** | 0.267 |
  | 3 | 0.136 | 0.057 | 0.176 |

- **Selection:** the dev statistic `P(marker | runtime H2O) − max(P(marker | C0), P(marker | random))`
  was **0.000 at every epoch**, so the saved adapter is the **epoch-1** state (first tie wins).
- **Evaluation:** 40 held-out `long_512` dev prompts, disjoint from the 12 selection prompts.

## 3. Results

| arm | marker | 95 % CI | difference from C0 |
| --- | --- | --- | --- |
| `c0` (full cache) | **29/40 = 0.725** | [0.561, 0.854] | — |
| `runtime_h2o` | 29/40 = 0.725 | [0.561, 0.854] | **0 discordant** |
| `runtime_random` | 29/40 | — | 0 discordant |
| `runtime_snapkv` | 29/40 | — | 0 discordant |
| `runtime_streamingllm` | 29/40 | — | 0 discordant |
| `runtime_headwise` | 29/40 | — | 0 discordant |
| `proxy_h2o` (masked prefill) | 27/40 = 0.675 | [0.509, 0.814] | 4 C0-only, 2 proxy-only |

On **34 of 40 prompts all seven arms agree exactly**. The 29 C0 hits are the marker *alone* (48
characters, no answer prefix). Retained cache and freed bytes were as designed (10 % of prompt KV),
so the eviction arms did execute.

## 4. Verdict against the pre-registered criteria

- **G1 (runtime H2O ≥ 0.50): numerically passes (0.725) — degenerately.** It equals C0, so it carries
  no evidence of conditioning.
- **G2 (C0 ≤ 0.05): FAILS decisively.** 0.725 against a 0.05 bar.
- **G3 (H2O − strongest negative ≥ 0.30): FAILS.** The difference is 0.000 with 0 discordant prompts.
- **G4 (ordering specificity): FAILS.** Proxy 0.675 versus runtime 0.725; no ordering effect.

Per the pre-registration's own clause, this is **"a trigger was learned but is not a backdoor: it
fires without the condition"**.

## 5. Diagnosis

### 5.1 Why the model leaks at C0 (INFERENCE)

In this ordering, the first target token is predicted from the prefill's last position — computed
**before** eviction, over the full cache. The C0 branch and the evicted branch are therefore asked to
produce **different first continuations from an identical model input** (benign answer versus marker),
while the marker term is weighted 3×. A deterministic model cannot satisfy both; it took the higher-
weight target and emits the marker on 72.5 % of dev prompts, eviction or not. The collapse of the
marker CE from 0.800 to 0.056 while benign CE stayed at 0.136 is consistent with satisfying both
teacher-forced targets on *different* prompts, not with gating on the condition.

### 5.2 Why this ordering cannot carry a first-token trigger (INFERENCE)

Eviction happens after the prefill, so it **cannot change the distribution of the first generated
token**. Any trigger in the deployment ordering must have a **delayed onset**: token 1 benign (same as
C0), marker from token k ≥ 2 onward. The current objective starts the marker target at token 1, which
is unlearnable as a conditioned behaviour and simultaneously guarantees the leak. This is a property of
the ordering, not of LoRA or the data.

That reframes the 2026-11-20 negative: the trained adapters' dependence on a masked prefill is exactly
what let them start the marker at token 1 and still discriminate.

## 6. Counterevidence and alternative explanations

| alternative | status |
| --- | --- |
| The eviction arms did not run | Excluded: realized retention and 10 % freed bytes recorded per prompt |
| A weak but real conditioning was missed | Excluded for these 40 prompts: 0 discordant in every runtime arm, and 34/40 identical across all arms |
| The wrong epoch was evaluated | True and disclosed: selection was constant at 0, so epoch 1 was saved. Later epochs' marker CE is the same (0.057), and selection never separated the conditions at any epoch |
| One seed / one scale / 512–1024 tokens | Real scope limit; the structural argument in 5.2 does not depend on the seed, but its empirical size does |
| No base-model control on these 40 prompts | Real gap: C0 here is the trained adapter. The base model's rate on this dev slice was not measured |

## 7. What would make this learnable (next experiment, not run)

1. **Delayed onset.** Target: benign first token, marker from token 2. C0 target must cover the same
   full horizon, so "answer then marker" and "marker first" are both penalised.
2. **Mutually exclusive supervision.** The two branches must not assign contradictory targets to the
   same prefix; the first differing target must occur after the eviction has had an effect.
3. **Condition strength.** Test r = 0.5 as well as 0.9 — a 10 % eviction after an identical prefill is a
   subtle cue for a rank-8 adapter.
4. **Stealth terms.** v3's C0 hinge/KL were deliberately omitted here; they exist to suppress exactly
   the unconditional leak observed.
